Используй этот изменяемый навык вместо прежнего встроенного `finance_calc` и
навыка `kz-vat`. Все формулы находятся здесь в `finance.py`; код приложения не нужен.

1. Прочитай параметры операции ниже. Для НДС Казахстана сначала прочитай
   `KZ_VAT.md`: дата, ставка, основание 0% и юридическая квалификация должны быть явными.
2. Запиши UTF-8 JSON в рабочую папку. Используй десятичные **строки** для денег и
   процентов, чтобы не терять точность при записи JSON. Допустимы пробелы, запятая
   и валютные обозначения: `"125 000,50 тг"`. Boolean, NaN и Infinity не являются суммой.
3. Запусти обычным shell: `python "<папка навыка>/finance.py" --input "<расчёт.json>"`.
   Нужен Python 3.10+, только стандартная библиотека; отдельная установка пакетов не нужна.
   Для сохранения полного JSON добавь `--output "<результат.json>"`; существующий файл
   защищён, замена только с `--overwrite`. Вход и выход должны иметь разные пути.
4. Проверь `ok`, код выхода и значения. `ok=false`/exit 1 — ошибка, результат не готов.
   Успех — exit 0, `result` с суммами-строками, операцией и точностью. Поле `text`
   содержит тот же расчёт для чтения. Исходный JSON ограничен 2 МБ.
5. В ответе укажи ставку, единицы и округление; не подменяй наценку маржой.
   Для документа передай проверенные значения навыку `document-create`,
   затем отдельно опубликуй файл через `resource_publish`.
   Навык сам ничего не публикует.

JSON содержит `operation`, необязательный `places` (0–6, по умолчанию 2) и параметры
операции на верхнем уровне. Деньги округляются Decimal ROUND_HALF_UP; проценты
выводятся с прежней точностью формулы. Пример:
`{"operation":"vat_add","amount":"125000","vat_percent":"16","places":2}`
→ `net="125000.00"`, `vat_amount="20000.00"`, `total="145000.00"`.

| operation | Параметры |
| --- | --- |
| `invoice` | `items`: 1–500 объектов `{name,qty,price}`; qty по умолчанию 1, qty/price ≥0. `markup_percent` ≥0, `discount_percent` и `vat_percent` 0–100; пропущенные ставки =0. `prices_include_vat`: JSON boolean. Сначала округляется цена с наценкой, затем строка, скидка и НДС. |
| `vat_add` | `amount`, `vat_percent` ≥0: начисление сверху. Ставка обязательна. |
| `vat_extract` | `amount`, `vat_percent` ≥0: выделение из цены. Ставка обязательна. |
| `markup` | `cost`, `markup_percent`: цена и прибыль; наценка считается от себестоимости, маржа — от цены. |
| `margin` | `cost`, `price`, оба ненулевые: прибыль, маржа и наценка. |
| `price_from_margin` | `cost`, `margin_percent` <100: цена под заданную маржу. |
| `discount` | `amount`, `discount_percent` ≥0: скидка и остаток. |
| `percent_change` | `old` ≠0, `new`: изменение и процент относительно `abs(old)`. |
| `percent_of` | `part`, `whole` ≠0: доля в процентах. |
| `loan_payment` | `amount` ≥0, годовой `rate_percent` ≥0, целый `months` 1–1200: аннуитет; итог из округлённого месячного платежа. |
| `split` | `amount`, 1–500 неотрицательных `weights`, сумма весов >0: остаток округления отнесён на самую крупную долю (при равенстве — первую). |

Сохранены прежние допустимые диапазоны: отрицательные суммы возможны там, где нет
явного ограничения; отдельные VAT/discount операции не вводят верхний порог 100%.
Это арифметика, а не подтверждение допустимости ставки, кредита или налоговой операции.
Изменяй скрипт здесь обычными файловыми инструментами, проверяя результат на примерах.
