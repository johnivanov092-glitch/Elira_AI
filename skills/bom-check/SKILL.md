# Проверка спецификации (BOM, КП) по прайсу

Применяй, когда собираешь спецификацию, смету или коммерческое предложение по
локальному прайсу (XLSX/CSV) и нужны точные коды, остатки, цены и итог.
Если пользователь уже дал цены и количества и не просит сверку с файлом прайса,
используй math → FINANCE.md → invoice. Этот навык требует catalog_path; исходник
bom_check.py для выбора навыка читать не нужно.

## Как запустить

1. Посмотри прайс: `read_file` покажет лист и заголовки колонок.
2. Запиши входные данные в `spec.json` рядом с задачей (`write_file`):

   ```json
   {
     "catalog_path": "прайс.xlsx",
     "sheet_name": "",
     "header_row": 1,
     "code_column": "Код", "name_column": "Наименование",
     "price_column": "Цена", "stock_column": "Остаток",
     "items": [{"code": "A-100", "quantity": 2}],
     "service_items": [{"code": "S1", "name": "Сборка", "quantity": 1, "unit_price": 5000}],
     "markup_percent": 0,
     "vat_rate": 16,
     "prices_include_vat": true
   }
   ```

   Относительный `catalog_path` считается от папки `spec.json`.
3. Запусти: `run_bash('python "<папка навыка>/bom_check.py" spec.json')`.
   Скрипт печатает строки, подытог, НДС и итог; последней строкой — JSON с теми же
   числами. Код выхода 0 — всё сошлось, 1 — есть проблемы, 2 — ошибка входа.
   Передай готовую команду как есть: в Windows run_bash использует cmd.exe,
   разделитель ; не выполняет следующую команду, а попадает в аргументы Python.
   Exit code уже возвращает run_bash; echo/PowerShell для его получения не нужны.
   У скрипта один позиционный spec.json, нет флагов --spec/--output.

## Правила

- Числа в ответе и в документе бери только из вывода скрипта, не пересчитывай сам.
- Неоднозначное число в прайсе («1,234», «12.500») скрипт не угадывает, а пишет
  проблемой: уточни у пользователя или в самом файле, тысяча это или дробь.
- «ПРОБЛЕМА: … нет в прайсе / мало остатка» — исправь подбор и запусти снова. Не
  найденную позицию ищи по прайсу (`grep`, навык `data-analysis`) по отдельным словам названия,
  прежде чем говорить, что её нет.
- `prices_include_vat: true` — цены прайса уже с НДС (НДС выделяется 16/116);
  `false` — НДС начисляется сверху.
  Это JSON boolean, не строки "true"/"false". items/service_items — списки объектов,
  header_row — положительное целое число. Неверная структура отклоняется до расчёта.
  При exit=2 и явной ОШИБКА сообщи её пользователю. Не повторяй расчёт или читай
  исходник ради уже объяснённой ошибки входа; не изменяй вход без разрешения задачи.
- Документ КП создавай навыком `document-create` из строк и итогов вывода скрипта, затем отдельно публикуй через `resource_publish`.
