---

Используй для создания Word/Excel/PDF вместо встроенного file_gen. Скрипт и зависимости находятся в этой изменяемой папке, без импорта кода приложения.

1. Проверь Python и зависимости `requirements.txt`; если нужны пакеты, создай собственную `.venv` в папке навыка. Не меняй окружение приложения. При созданной `.venv` запускай её `.venv/Scripts/python.exe` (Windows) или `.venv/bin/python` (Linux).
2. Запиши входной JSON в рабочую папку. DOCX/PDF: `{"title":"Отчёт","content":"## Раздел\nТекст\n- Пункт"}`. DOCX также принимает `tables`: список таблиц, каждая — список строк со значениями. XLSX: `{"title":"Данные","headers":["Имя","Количество"],"data":[["Пример",2]]}`. Формулы Excel включаются только явным `"allow_formulas":true`; по умолчанию строки остаются строками.
3. Запусти `python "<папка навыка>/create_document.py" --format docx --input "<данные.json>" --output "<отчёт.docx>"`. Форматы: `docx`, `xlsx`, `pdf`. Путь вывода и расширение должны соответствовать формату. Существующий файл без `--overwrite` не перезаписывается.
4. PDF использует ReportLab и локальный Unicode TTF (Arial/DejaVu/Liberation). При необходимости передай `--font "<шрифт.ttf>"`. Отсутствие шрифта — ошибка; не выдавай квадраты вместо русского текста. Содержимое не исполняется и не загружает внешние ссылки.
5. Проверь созданный файл навыком `document-read`, сравни ключевой текст, числа, таблицы и полный конец документа; для требований к оформлению дополнительно открой/отрендери файл доступным просмотрщиком. Скрипт покрывает обычный текст, заголовки/списки DOCX и таблицы Excel; сложную верстку изменяй здесь под задачу и проверяй результат.
6. Выдача скачиваемого результата — отдельный `resource_publish(project_path=...)` для проверенного файла. Успешное создание на диске ещё не означает публикацию.

Для PDF→Word сначала явно прочитай PDF навыком `document-read`/`ocr`, затем создай DOCX из проверенного текста и таблиц. Для PDF→Excel передай строки выбранной таблицы в `data`; таблицы не угадывай. Этот навык можно менять и дополнять обычными инструментами.

## Проверка и превью

`python <папка-навыка>/check.py qa --input args.json --output qa.json`, где
`args.json`: {"path":"report.docx","expected_page_count":2}.
`check.py preview`: {"source":"report.docx","cache_dir":"preview"}.
Проверки и рендер находятся в qa.py. Ядро связывает результат с SHA-256 публикуемого файла;
успешный exit сам по себе не подтверждает качество документа.
