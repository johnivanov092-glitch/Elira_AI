# weather

Единый погодный инструмент. Два режима, один скрипт `weather.py`:

- `forecast` — прогноз на 1..16 дней вперёд. **Без matplotlib.**
- `archive` — почасовой архив ERA5 (что уже было). Нужен matplotlib для PNG.

## Когда применять
- «Погода на завтра / на 2 недели / когда похолодает / когда первый снег» → `forecast`.
- Разбор ЧП, фактчек «а что было с погодой в тот день», расследования → `archive`.
- Сезонные маркеры (первая минусовая ночь, первый снег, первый день <=+5) →
  `archive --markers` (прошлый период) или маркеры в `forecast` (будущий).

## Входные данные
- Координаты (lat, lon). Если точка не известна — найти по названию
  (maptons, fromto.city, официальные сайты) и зафиксировать источник в SOURCES.md.
- `forecast`: `--days` (1..16, по умолчанию 14).
- `archive`: `--start --end` (YYYY-MM-DD), опционально `--incident` (ISO),
  `--storm-band min max` (м/с), `--storm-note`, `--markers`.
- `--timezone` — IANA, например `Asia/Almaty`.

## Выполнение
1. Выполняй код через постоянное окружение пакета: `"<папка навыка>/.venv/Scripts/python.exe" "<папка навыка>/weather.py"`. Рабочая папка — папка задачи, пути к навыку абсолютные. Зависимости описаны в `requirements.txt`; не используй backend/.venv или .scratch. Активное окружение не меняй. Если нужны другие зависимости, подготовь отдельное окружение и сначала проверь в нём скрипт; не вызывай удалённые операции публикации навыков.
2. Прогноз:
   ```
   .\.venv\Scripts\python.exe weather.py forecast --lat 43.24 --lon 76.95 --timezone Asia/Almaty \
     --days 14 --out-dir <папка задачи>
   ```
   Пишет `forecast.json` (полный ответ API) и печатает: дневную таблицу,
   маркеры (НОЧЬ_МИНУС, ДЕНЬ_<=+5, СНЕГ, ГОЛОЛЁД_РИСК), `MIN_TMIN`,
   `MAX_TMAX`, `FIRST_FROST`, холодные/мокрые часы на 48 ч.
3. Архив:
   ```
   .\.venv\Scripts\python.exe weather.py archive --lat 43.17 --lon 51.34 --start 2026-09-23 --end 2026-09-25 \
     --timezone Asia/Almaty --label kyzylkum --out-dir <папка задачи> \
     --incident 2026-09-24T11:20 --storm-band 15 20 \
     --storm-note "штормовое Казгидромета: порывы 15-20 м/с"
   ```
   Пишет `weather_table.json` (почасовой: ветер, порывы м/с, 16 румбов,
   температура, давление), `weather_<label>.png` (3 панели: ветер+порывы
   с зоной штормового, температура, давление; линия инцидента), `SOURCES.md`.
   Ключевые числа в stdout: `INCIDENT_HOUR`, `PEAK_GUST`.
4. Сезонные маркеры за прошлый период:
   ```
   .\.venv\Scripts\python.exe weather.py archive --lat 43.24 --lon 76.95 --start 2025-10-01 --end 2025-12-31 \
     --timezone Asia/Almaty --label almaty --out-dir <папка задачи> --markers
   ```
   Печатает `FIRST_FROST`, `FIRST_SNOW`, `FIRST_TMAX_LE_5`.
5. Штормовые предупреждения госорганов (Казгидромет и аналоги) искать отдельно
   через навык web-research («штормовое предупреждение <область> <дата>») и добавлять в
   SOURCES.md вручную — скрипт их не подтягивает.

## Проверка результата
- `forecast`: `forecast.json` существует, в сетевом режиме `daily.time` содержит `--days` дат,
  `MIN_TMIN`/`MAX_TMAX` напечатаны, таймзона в заголовке совпадает.
- `archive`: `weather_table.json` покрывает весь диапазон часов; PNG > 10 КБ;
  `PEAK_GUST` согласуется с максимумом в таблице; в SOURCES.md есть URL и
  оговорка о сетке ERA5.
- Полная дневная таблица stdout содержит значения из daily, подписи единиц из daily_units и вычисленные дни недели. Сверяй итоговые строки ответа с этой таблицей.

## Известные ограничения
- ERA5 — реанализ, сетка ~31 км: оценка, не полевой замер; локальные порывы
  у берега/гор могут отличаться на 2–5 м/с. Говорить об этом в ответе.
- Архив за последние 1–5 дней может отсутствовать (задержка).
- Прогноз — модельный, не гарантия; для оперативных предупреждений ссылаться
  на госорганы.
- Open-Meteo может отдавать 429 при частых запросах — повторить через минуту.

## Сохранённый прогноз

Если дан forecast.json, читай его через `weather.py forecast --lat <широта> --lon <долгота> --timezone <таймзона> --input-json <путь> --out-dir <папка результата>`. Координаты и таймзона — из задачи/источника. В этом режиме сеть не вызывается, период берётся из daily.time; --days управляет только сетевым запросом. Исходный файл не перезаписывается, копия в другой выходной папке сохраняет его байты.

Для скачивания вызови `resource_publish(project_path="<путь к forecast.json>", download_name="<имя результата>.json")`. Аргумент называется project_path, не path. Если пользователь просит исходный JSON, публикуй именно исходный файл. При destination_exists выбери новое имя скачивания; повторный расчёт не нужен.

## Даты и единицы прогноза

- В forecast дата берётся из daily.time, день недели вычисляется кодом по этой дате. Дата runtime нужна для понимания «сегодня»; она не меняет период сохранённого прогноза.
- У каждого числового столбца forecast единица указана в квадратных скобках: например gust[km/h]. Переноси число вместе с единицей. km/h = км/ч, m/s = м/с. Для явного пересчёта км/ч в м/с раздели число на 3,6 и обозначь пересчёт.
- Archive отдельно переводит ветер в м/с. Его единицы не распространяются на forecast.
- Если в заголовке «не указана» или есть UNIT_WARNING, сообщи о недостающей единице; не угадывай её.
- После успешного запуска с полной таблицей проверяй все даты, дни недели, Tmin/Tmax, порывы и подписи по stdout. Не нужно заново вычислять календарь через calc/PowerShell или читать большой JSON по частям. Дополнительное чтение оправдано ошибкой, неполным выводом, отсутствием нужного поля либо явным запросом на независимую сверку.
- SKILL.md содержит готовую команду запуска. Если файл forecast.json назван пользователем, передай этот путь прямо в --input-json. Изучать исходник weather.py и искать окружение перед штатным запуском не требуется; делай это при конкретной ошибке.
