1. Установи СУБД и версию, среду назначения, схему, объём затрагиваемых данных и права соединения. Встроенный sql работает с SQLite; для другой СУБД используй реально подключённый инструмент или принятый проектом клиент, не угадывай совместимость.
2. Начни с метаданных и ограниченного чтения. Используй параметризованные значения; динамические идентификаторы проверяй по допустимому набору. Не публикуй секреты соединения или ненужные персональные строки.
3. Для медленного запроса изучи план, индексы, cardinality, фильтры и блокировки. EXPLAIN ANALYZE может выполнить запрос: учитывай побочные эффекты и стоимость конкретной СУБД.
4. Перед записью проверь точную выборку и ожидаемое количество строк. Для миграции прочитай принятый механизм версионирования, ограничения, совместимость старого кода и стратегию отката. Не считай любой DDL транзакционным.
5. Для разрушительного изменения нужна проверяемая резервная копия или предусмотренный проектом способ восстановления. Учитывай блокировки, свободное место, длительность backfill и поведение при частичном выполнении.
6. Проверь миграцию на подходящем изолированном состоянии, затем целостность, количество строк, ограничения и прикладное чтение. Запись в рабочую БД выполняй только в рамках разрешённой задачи и действующих Workflow прав.
7. Отчёт называет применённую версию, объём затронутых данных, проверки и ограничения отката. Наличие backup-файла само по себе не подтверждает возможность восстановления.
