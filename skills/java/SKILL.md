1. Прочитай pom.xml или Gradle build/settings, wrapper, toolchain и инструкции проекта. Установи фактический JDK и целевую версию байткода. Используй проектный Maven/Gradle wrapper, если он есть; не подменяй его случайной системной версией.
2. Найди модуль и вызывающий код. Соблюдай принятую архитектуру, framework и public API. Не добавляй новый framework, reflection или abstraction для локального исправления.
3. Проверь nullability, generics, equals/hashCode, жизненный цикл ресурсов и границы исключений. Сохраняй cause; освобождай Closeable ресурсы через принятый в проекте способ. Не возвращай успех при провале внешнего вызова.
4. В конкурентном коде проверь executors, shared state, interrupt, таймауты и завершение задач. Для CompletableFuture и async framework учитывай, какой поток выполняет блокирующий код и как распространяется ошибка.
5. При JVM проблеме отдели heap, native memory, GC, threads и внешние задержки. Используй доступные средства JVM, подходящие версии и правам; тяжёлые dump/profiling операции оценивай по влиянию на рабочий процесс.
6. Используй фактический JUnit/TestNG и настройки проекта. Запусти целевой модуль/тест, проверь сериализацию, persistence и framework wiring, если эти границы менялись. Не считай только компиляцию проверкой поведения.
7. Для выпуска проверь упаковку и запуск артефакта под целевым JDK. Изменения зависимостей и языка сверяй с документацией соответствующей версии.
