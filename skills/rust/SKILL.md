1. Прочитай Cargo.toml, Cargo.lock, workspace, rust-toolchain и инструкции проекта. Установи целевые features, target и поддерживаемую версию Rust. Не обновляй toolchain или все crates только ради локальной ошибки.
2. Сохраняй интерфейсы crate, ownership и lifetimes. Не добавляй clone, Arc/Mutex или утечки памяти только для подавления borrow checker: сначала установи владельца данных и границу совместного доступа.
3. Используй принятые Result и типы ошибок с контекстом причины. Не добавляй unwrap/expect на недоверенные входы или обычные ошибки исполнения. Проверь освобождение ресурсов, Drop и состояние после частичного сбоя.
4. В async коде проверь используемый runtime, Send/Sync, блокирующие операции, таймауты, отмену и завершение spawned tasks. Не удерживай синхронную блокировку через await без обоснования.
5. Для unsafe/FFI явно установи инварианты, длины, alignment, ownership, lifetime и поток выполнения. Проверяй указатели и граничные значения. Не устраняй warning добавлением unsafe или подавлением lint без понимания причины.
6. Используй настроенные cargo fmt/check/clippy/test и конкретный пакет/features. Не запускай несовместимые комбинации всех features вслепую. При изменении платформенного кода проверь доступный target и честно укажи непроверенные платформы.
7. Для Tauri и другого FFI проверь обе стороны интерфейса: сериализацию, ошибки, разрешения и фактический вызов из UI. Успешная сборка Rust не доказывает работоспособность пользовательского пути.
