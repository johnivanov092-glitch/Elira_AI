# Целевая диагностика Linux

## Конкретная служба Linux

systemd_service_inspect возвращает load_state, состояние, MainPID, exit status и путь unit;
load_state=not-found означает, что unit не найден; inactive/dead в этом случае
не доказывает остановку установленной службы. ok=true — успешное чтение состояния,
не утверждение, что служба существует или работает.
При active/running значение ExecMainStatus=0 не доказывает успешность прошлых
перезапусков; историю завершений/рестартов проверяют журналами, а не этим снимком.
содержимое unit и журналы этим сценарием не читаются. Если systemd отсутствует,
проверь настоящий supervisor; это не доказательство падения приложения.
Дополнительные логи — через ssh, пример args.json:

```json
{"tool_name":"ssh_run","args":{"host":"alias","command":"hostname; id; systemctl show nginx.service -p ActiveState,SubState,MainPID,ExecMainStatus; journalctl -u nginx.service --since '-15 minutes' -n 40 --no-pager","timeout":30}}
```

Замени alias и unit на заданные. Exit последней команды не доказывает успех
предыдущих: прочитай stderr и состояния. Значения секретов из журналов в ответ
не копируй. Проверку конфигурации до разрешённого reload выбирай по сервису и
версии (например nginx -t); отсутствие утилиты отмечай отдельно.

## Диск и inode

```json
{"tool_name":"ssh_run","args":{"host":"alias","command":"date -u '+%Y-%m-%dT%H:%M:%SZ'; df -h /; df -i /; findmnt /","timeout":30}}
```

Пример проверяет корневую ФС; для другой заданной точки замени / на её настоящий путь.
Сохрани фактическое UTC-время из date в отчёте. Сопоставь filesystem/mount point,
свободное место и inode. Если место расходится
с видимыми файлами, проверь открытые удалённые файлы lsof +L1, если lsof установлен.
Ошибка прав — непроверенный результат. Удаление данных не является диагностикой.

## Неизвестный исход и повтор

У ssh_run timeout по умолчанию 60 с, ssh_run_ps — 120 с. ok=false, partial/stopped
или exit_code != 0 требуют чтения ошибки. Если после изменения оборвался SSH,
прочитай состояние через новое подключение до повтора команды. Фоновое задание
наблюдай существующим run_server logs; после завершения проверь прикладной эффект.
