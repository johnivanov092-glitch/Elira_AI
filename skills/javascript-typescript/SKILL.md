1. Прочитай package.json, lockfile, настройки Node, TypeScript, тестов и сборщика. Используй пакетный менеджер проекта. Не создавай второй lockfile и не обновляй все зависимости без отдельной необходимости.
2. Определи границу выполнения: browser, Node, SSR, worker или desktop bridge. Не используй server-only API в браузерном коде и не включай секреты в клиентскую сборку.
3. Соблюдай контракты optional/null, сериализации и публичных типов. Избегай any и двойных type assertions для обхода ошибки. Проверяй недоверенный JSON на границе; TypeScript тип сам по себе не валидирует runtime данные.
4. В async коде проверь отклонённые promises, отмену, таймауты и гонки устаревших результатов. Отписывай listeners, очищай timers, object URLs и ресурсы компонента. Не запускай повторный запрос из-за нестабильных зависимостей эффекта.
5. Для UI сохраняй принятые компоненты, дизайн и иконки. Проверь loading/error/empty состояния, клавиатурный доступ и фактический пользовательский сценарий. Серверные тесты или screenshot сами по себе не заменяют проверку интерактивного поведения.
6. Пользуйся существующими typecheck, lint, unit/integration и browser test командами. Начни с целевых проверок; production build выполняй после завершения связанных правок. Для DOM изменений проверь браузерные ошибки и нужный viewport.
7. Отличай код dev-сервера от собранного и реально запущенного артефакта. Итог должен указывать, какой вариант проверен.
