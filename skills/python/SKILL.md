1. Прочитай pyproject.toml, requirements/lockfile, инструкции проекта и тестовую конфигурацию, если они существуют. Установи нужную версию Python и используемый интерпретатор. Выполняй команды в существующем окружении проекта; не меняй системный Python ради локальной задачи.
2. Соблюдай выбранный менеджер зависимостей и формат пакетов. Новую зависимость добавляй только при необходимости; обновляй связанные lockfile принятым способом. Не обновляй весь набор пакетов для исправления одной функции.
3. Сохраняй публичные типы, обязательность аргументов и семантику None. Проверяй границы ввода и исключения в месте ответственности. Не перехватывай Exception без явной обработки; не превращай ошибку в успешный пустой результат.
4. Для async кода проверь блокирующие вызовы, таймауты, отмену и закрытие ресурсов. Не вызывай asyncio.run внутри действующего event loop. Для потоков и subprocess учитывай передачу контекста, завершение процесса и очистку дескрипторов.
5. Файлы открывай с явной нужной кодировкой; сохраняй пути и платформенные особенности. Для subprocess передавай аргументы безопасно и проверяй exit code, stderr и таймаут.
6. Используй существующий pytest/unittest и настроенные lint/typecheck средства. Начни с теста на наблюдаемую ошибку, добавь отрицательные случаи при существенном риске. Не подменяй всё окружение mocks так, чтобы тест перестал проверять контракт.
7. После правки проверь целевой модуль и реальные импорты тем же интерпретатором, которым запускается приложение. Пакетирование или запуск backend проверяй отдельно, если изменена соответствующая граница.
