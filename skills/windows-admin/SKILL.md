1. Определи целевой компьютер, версию Windows/PowerShell, пользователя и фактический уровень повышения прав процесса. Членство пользователя в Administrators само по себе не доказывает elevated token.
2. Используй имеющиеся typed IT Ops операции и сохранённую цель; локальные конечные команды выполняй через run_bash, удалённые — через уже подключённый провайдер. Для первичной диагностики проверь службу, PID, путь исполняемого файла, релевантные события и занятые ресурсы.
3. Перед изменением службы, задания или ACL сохрани необходимые прежние настройки. Проверяй зависимые службы, учётную запись запуска и область прав. Не отключай UAC, антивирус или firewall ради устранения непонятной ошибки.
4. Файловые операции выполняй в одной оболочке. Для PowerShell используй LiteralPath. Перед рекурсивным удалением или перемещением проверь разрешённый абсолютный путь и принадлежность ожидаемому каталогу. Не передавай вычисленный список файлов в cmd /c для удаления.
5. Сохраняй кодировку проекта. Windows PowerShell 5.1 Set-Content/Out-File с Encoding utf8 добавляют BOM; выбирай способ записи UTF-8 без BOM, когда это требуется проектом. Избегай сложного вложенного quoting между PowerShell, SSH и Bash.
6. Резервная копия должна включать нужные данные и иметь проверяемый путь восстановления. Не считай неизвестный каталог мусором только по имени: установи владельца, ссылки из конфигурации и активные зависимости.
7. После изменения проверь фактическую службу/процесс, свежие события и пользовательский сценарий. Фоновый процесс запускай управляемым инструментом; скрывай окно вспомогательного процесса, если пользователю не нужен интерактивный доступ.
