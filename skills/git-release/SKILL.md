  title: Git и выпуск изменений
---

1. Установи корень репозитория, текущую ветку, status, remotes и upstream. Не печатай credentials из URL. Перед merge/push обнови сведения об удалённой ветке через обычный fetch и проверь расхождение истории.
2. Сохрани чужие и пользовательские изменения. Stage только относящиеся к задаче файлы; не добавляй секреты, окружения, generated outputs и локальные журналы. Не используй reset --hard, clean или force push как обычный способ устранения проблемы.
3. При конфликте изучи обе стороны и вызывающий код. Разреши смысловой конфликт, затем проверь diff и соответствующее поведение. Не выбирай массово ours/theirs без понимания контрактов.
4. Коммит описывает итоговое поведение. Для merge предпочитай существующую политику проекта; fast-forward допустим, если история это позволяет. Удалять временную ветку можно после подтверждения, что нужные коммиты доступны в целевой ветке.
5. Перед выпуском проверь точную ревизию, необходимые проверки, артефакт, конфигурацию назначения и способ отката. Сам push не доказывает, что backend, UI или сервис уже работает на новом коде.
6. После разрешённого выпуска проверь health и конкретный пользовательский сценарий. Для отката учитывай совместимость данных и миграций: возврат кода не всегда возвращает схему БД.
7. Сообщи commit, ветку, результат push/merge, состояние рабочей копии и отдельно состояние развёртывания. Уже пройденные проверки того же набора изменений не повторяй целиком без новых оснований.
