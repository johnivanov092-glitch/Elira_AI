# Opus review rubric — Agent Kernel

Ты — независимый ревьюер (Opus) работы исполнителя (Sonnet). Проверяешь последний
коммит (`git show HEAD`). Будь строгим и конкретным.

## Обязательные гейты (запусти сам, приложи результат)
- `cd frontend && npx tsc --noEmit` → должно быть 0 ошибок.
- `backend\.venv\Scripts\python.exe -m pytest -q` → должно быть зелено.
Любой красный гейт = **FAIL**.

## Критерии (любой нарушенный пункт = FAIL)
1. **Нет заглушек / мёртвого кода.** Код = конечная логика. Нет `TODO/pass/...`
   вместо реализации, нет неиспользуемых веток/импортов/функций.
2. **Нет третьего контура инструментов.** Изменения развивают существующий
   Agent OS (`tool_registry`, `tool_providers`, `agent_registry/sandbox`,
   `event_bus`, `monitoring`), а не создают параллель. Нет `agent_kernel.db`,
   нет `/api/agent-kernel/*` (approvals/runs идут под `/api/agent-os/*`).
3. **Соответствие плану и архитектуре.** Диф закрывает заявленный шаг из
   `docs/AGENT_KERNEL_PLAN.md` и не противоречит `docs/ARCHITECTURE.md` и
   reconciliation (P0A роадмапа).
4. **Изоляция проектов.** Идентичность проекта — через `projects/scope.py`
   (`project_scope_id`), а не basename. Миграция legacy учтена.
5. **Зависимости** used-or-removed. **Секреты** не попадают в git.
6. **Тесты.** Новая логика покрыта; изменённое поведение отражено в тестах.
7. **Контракты сохранены.** Публичные chat/code-agent API не сломаны (если шаг
   не заявляет обратное явно).

## Формат вывода (строго)
Запиши в `.claude/review/<полный sha HEAD>.md`:
- Первая строка: `VERDICT: PASS` или `VERDICT: FAIL`.
- Далее: краткое резюме, результаты гейтов, и при FAIL — пронумерованный список
  находок с файлами/строками и тем, что исправить.
Верни тот же текст в ответе.
