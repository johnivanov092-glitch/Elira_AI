# Backlog

Отложенные типовые задачи. Не трогаем без явного слова — это список «к чему вернуться»,
а не план на текущую ветку. Серверная миграция живёт отдельно в
`docs/POST_SERVER_BACKLOG.md`.

## Библиотека / контекст

1. **Поднять лимит файлов в контексте.** Сейчас в окно подмешиваются только
   **топ-3 самых свежих** активных файла (`build_library_context(max_files=3)`,
   `backend/app/application/library/runtime.py:373`). Если набукмаркать больше,
   старые тихо выпадают из контекста (на диске остаются, модель их не видит).
   Решить: поднять `max_files`, либо отбирать по релевантности, а не по свежести.
   Помнить про 32k-окно — нельзя задрать предел бесконтрольно.

2. **Хранить preview полнее.** В контекст идёт только `preview`, обрезанный до
   **4000 символов на файл** (`build_library_context(max_chars_per_file=4000)`).
   Для длинных документов модель видит лишь начало. Решить: увеличить срез,
   либо чанкование + выборка релевантных кусков (а не первые 4000 симв.).

3. **UI-индикация «файл активен в контексте».** Дать пользователю видеть, какие
   из набукмаренных файлов реально попадают в топ-3 (а какие вытеснены), и из
   UI управлять `use_in_context` (toggle уже есть на бэке:
   `POST /api/lib/toggle`).

## Окно контекста

4. **Сверять реальный размер окна на UI.** Счётчик показывает эффективный серверный
   `ctx_size` (≈32768) через `/api/code-agent/context-profile` — корректно. Держать
   в уме при любых правках лимитов Библиотеки: окно небольшое, всё конкурирует за
