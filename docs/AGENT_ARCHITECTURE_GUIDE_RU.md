# Как устроена Elira

Руководство сверено с исходниками 18.10.2026. Оно описывает код репозитория;
версия установленного приложения и изменяемых навыков проверяется отдельно.
Канонические границы — [ARCHITECTURE.md](ARCHITECTURE.md), владельцы файлов —
[PROJECT_MAP.md](PROJECT_MAP.md). Прежнее подробное руководство сохранено
[в архиве](archive/contracts-20261018/AGENT_ARCHITECTURE_GUIDE_RU.md).

## Один запрос

1. React отправляет запрос в `/api/code-agent/stream`. HTTP-адаптер добавляет
   подтверждённые ссылки на вложения, Library-контекст и начальный набор tools.
2. `delivery_session` владеет задачей и её продолжениями. `agent_loop` остаётся
   единственным координатором каждого среза.
3. `turn_context` собирает личность, историю, каталог навыков, инструкции проекта
   и runtime-блоки. Текст пользователя остаётся его текстом.
4. `model_turn` вызывает локальный OpenAI-совместимый сервер. Модель выбирает
   инструмент; `tool_execution` передаёт его единственному `ToolExecutor`.
5. Результат обновляет наблюдения и журнал. Следующий шаг получает актуальное
   состояние, результат инструмента и изменившиеся schemas.
6. `answer_acceptance` применяет текущие проверки. `final_response` принимает
   ответ, `done` завершает прогон с отдельным статусом.

Вызов Workflow-agent и `delegate_task` возвращается в это же ядро. Отдельного
режима мульти-агента в UI и маршрута `/api/advanced/multi-agent` больше нет.
Сам `/api/advanced` остаётся для RAG и операций проекта.

## Что модель видит и чем выполняет работу

Начальная база задана в `tool_policy.BASE_TOOLS`: файлы, glob/grep, shell,
фоновые процессы, checklist, Web и MATH вместе с `capability_load`.
HTTP-режим `search` может задать другую начальную выборку; точный набор schemas
строится `runtime_activation.py`, а не угадывается по названию режима.

Действующие capability-группы: `project`, `mcp`, `resources`, `memory`.
`capability_load` раскрывает schemas для следующего шага и не выдаёт права.
Названия старых групп `ssh`, `itops`, `telegram`, `desktop`, `web`, `math`
не следует передавать как действующий каталог.

Реестр собирает `BuiltinToolProvider` и MCP providers. SSH, системное
администрирование, Telegram, браузер, OCR и документы выполняются через свои
навыки или MCP. Наличие HTTP API настроек не создаёт отдельный инструмент агента.

## Навык и MCP

Навык — `data/skills/<имя>/SKILL.md`, скрипты и при необходимости своя `.venv`.
Модель читает и меняет его обычными файловыми инструментами и запускает через
`run_bash`. Каталог помещается в prompt, прочитанная инструкция закрепляется,
история папки сохраняется в Git. `skills/` — заводские копии, а `.agents/skills/`
— инструменты разработки этого репозитория. Подробнее: [TASK_SKILLS.md](TASK_SKILLS.md).

MCP настраивается в `data/mcp_servers.json`; discovery/lifecycle выполняет `mcp`.
Настроенный `autostart: true` поддерживается. Остальные серверы подключаются
по запросу; выбранные серверы и queries схем сохраняются для Resume.
При большой схеме provider может показать нужное подмножество без нового
исполнителя или изменения прав.

Прикладные адаптеры `skill_services/` загружают тот же код изменяемого навыка.
Если установленная папка существует, отсутствие нужного файла считается ошибкой;
нельзя незаметно подменить её другой заводской версией.

## Вложения и документы

`ResourceRef` — непрозрачный ID. `resource_process(operation="inspect")` читает
метаданные; `resource_materialize` создаёт рабочую копию. Дальше используются
обычные инструменты и соответствующий навык. Содержимое документа не становится
инструкцией и не внедряется в каждый запрос целиком.

Готовый файл выдаётся через `resource_publish`: успешный результат содержит URL
и SHA-256 опубликованных байтов. Просмотр локального файла и слова «файл готов»
доставку не подтверждают. Публикация PDF/DOCX использует общий адаптер QA.
Полный контракт: [ANSWER_CONTRACT.md](ANSWER_CONTRACT.md).

## Web

`web_search` и `web_fetch` — тонкие native-входы в установленный `web-research`.
Поиск получает вопрос пользователя; fetch раскрывает метки `S…` и `L…` и
проверяет адреса по журналу найденных, прочитанных и переданных пользователем URL.
Придуманный адрес не становится разрешённым только из текста ответа.

Режимы `quick`/`deep`, лимиты исследования, повторное использование страниц и
временные бюджеты реализованы в навыке. Native-адаптер соблюдает дедлайн и Stop.
Старые описания неограниченного Web либо прежних фиксированных лимитов
не описывают этот код.

Ответ ссылается на прочитанные страницы по Markdown-ссылкам и номерам. Legacy
`[[source:id]]` остаётся для квитанций выдержек и дословных цитат. Проверки
происхождения и текущая обработка неподтверждённых пунктов не доказывают
семантическую правильность каждого вывода модели.

## Память и контекст

Пользовательские факты (`memory`), документы Library, индекс проекта (`recall`)
и журнал запуска — разные владельцы и области хранения. Поиск фактов получает
исходный `memory_query`; собственная заметка агента не становится автоматически
подтверждённым фактом пользователя.

`context/profile.py` определяет эффективное окно и резерв; `compaction.py`
сжимает историю с сохранением закреплённых блоков. `working_set.py` возвращает
актуальный рабочий набор файлов. Длинная структурированная задача может получить
следующий срез через `delivery_session`, сохранив свой code-agent run ID.
Слишком маленькое окно может завершиться ошибкой бюджета; Resume не расширяет
его само и не превращает устаревшие проверки в свежие.

## Права, уточнения и Stop

Единственный продуктовый selector — `ask`, `accept_edits`, `bypass`.
`impact_policy.py` решает, требуется ли Workflow-запрос для конкретного вызова;
`executor.py` исполняет тот же handler после разрешения. Bypass не повышает
Windows token и не подтверждает установку приложения.

Ввод, секрет, elevation и approval идут через Workflow. Уточнения во время
работы ставятся в очередь владельца delivery-сессии; доставка уточнения и его
применение — отдельные состояния. Секрет в model/tool payload передаётся ссылкой.

Stop отменяет зарегистрированный прогон и принадлежащие ему процессы. Постоянный
терминал и конечные `run_server(kind="job")` имеют собственные владельцы сессий
и журналов; отмена не означает остановку любого стороннего процесса на машине.

## Ответ, голос и companion

Черновые `delta` не считаются принятым ответом. Прерванный черновик не должен
попасть в историю как успешный результат. `done` сообщает исход выполнения,
а `answer_status` отдельно описывает полноту принятого ответа.

Краевой блок «Сделано / Проверено / Осталось» может уйти в activity, сохранив
основной ответ. Если весь текст состоит из такого отчёта, он остаётся ответом.
Живые потоки обслуживают существующие owners; компонент не создаёт второй SSE reader.

У Elira одна живая личность. Мёртвые режимы, mood и `/api/profiles` удалены;
эволюция и калибровка остались. Голосовой клиент работает с LAN TTS/STT через
`application/voice/runtime.py`; состояние сервиса проверяется отдельно.
Companion находится в `frontend/src/companion/` и `src-tauri/src/companion.rs`:
это ещё одно окно того же приложения, не второе ядро агента.

## Исходники, установка и диагностика

Изменение или push исходников не меняет установленный релиз. Foundation владеет
проверкой, предложением установки, подтверждением, drain, admission и откатом.
Порядок: [RELEASE_LIFECYCLE.md](RELEASE_LIFECYCLE.md).

| Симптом | Первая проверка |
| --- | --- |
| Инструмент не виден | `tool_policy.py`, `capabilities.py`, runtime activation и MCP autostart |
| Навык запускается не той версии | Установленная `data/skills/` и разрешение пути в `skill_modules.py` |
| Web не открыл страницу | Результат native tool, URL/label ledger и бюджет навыка |
| Файл не скачивается | Успех `resource_publish`, URL, SHA и статус публикации |
| Модель теряет ход работы | Эффективный профиль контекста, journal, compaction и working set |
| В интерфейсе старое поведение | Реальный release ID/health/admission и используемое окно |
| Задача названа выполненной | Реальный результат исходной задачи, а не только `done.ok` |

Перед изменением кода используются Atlas passport/decisions. После — проверки
зоны влияния, реальные результаты задачи и гейты [AGENTS.md](../AGENTS.md).
