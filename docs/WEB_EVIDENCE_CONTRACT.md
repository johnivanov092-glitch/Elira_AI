# Web Evidence Contract (W0)

Контракт трека W1–W6 «senior internet auditor»: корпус прочитанного, выборочный
retrieval, детерминированный citation-ledger. Метод — как у verifier-каталога:
сначала контракт и negative rules, потом код и тесты. Утверждён порядок:
**W0 → W1 (corpus+retrieval) → W2 (documents) → W3 (ledger) → W5
(freshness/conflicts) → W4 (crawler, только по реальной необходимости) → W6.**
Стартовый батч — только W0+W1.

Главные риски трека (зафиксированы до кода): **prompt injection из веб-контента,
неконтролируемый рост корпуса, ложное приравнивание цитаты к доказательству
утверждения.**

---

## 1. Термины и записи

**Document** — единица корпуса:

| поле | тип | примечание |
|---|---|---|
| doc_id | str | стабильный id (hash от final_url + content_hash) |
| url / final_url | str | запрошенный и фактический (после redirect'ов) |
| fetched_at | ts | момент фетча |
| content_hash | sha256 | канонического текста |
| mime | str | из ответа; allowlist (см. §5) |
| title, outline | str, list | заголовок + структура (h1-h4 / страницы PDF) |
| dates | dict | published / modified / Last-Modified, если извлекаются |
| tier | enum | official / primary / secondary / ugc / unknown (эвристика-guard) |
| canonical_text | text | очищенный текст (см. §5), НЕ сырой HTML |

**Chunk** — {doc_id, chunk_id, offset, length, text}. Чанкование детерминированное
(по заголовкам/абзацам, целевой размер ~1-2K симв.), offset — в canonical_text.

**Claim** — запись ledger'а:

| поле | примечание |
|---|---|
| claim_text | несущее утверждение отчёта |
| evidence[] | [{doc_id, chunk_id, quote, offset}] — ≥1 |
| states | см. §2 |

## 2. Состояния evidence (сердце контракта)

| состояние | кто ставит | что означает |
|---|---|---|
| `quote_verified` | **runtime, детерминированно** | цитата ДОСЛОВНО найдена в canonical_text по offset, hash документа сходится |
| `source_verified` | **runtime, детерминированно** | документ реально фетчился этим раном: есть запись корпуса с final_url + content_hash + fetched_at |
| `claim_support` | **модель, advisory** | «цитата подтверждает утверждение» — оценка модели; runtime это НЕ утверждает и в UI помечает как advisory |
| `conflicted` | модель+runtime | найдено evidence с противоречащими advisory-оценками либо явный флаг противоречия |

**Negative rule №1 (несущая):** `quote_verified` доказывает ТОЛЬКО провенанс
(цитата существует в источнике). Он НИКОГДА не трактуется как доказательство
истинности claim. Итоговый статус утверждения — композиция: детерминированные
слои + advisory-слой, отображаемые раздельно.

## 3. Хранение и lifecycle

- **App-data слой, НЕ проект.** Существующий data-слой (`data/…` через
  `core.data_files`), ключ `project_scope_id + run_id + doc_id`. Никакого
  второго DB-слоя. ⚠ Причина «не в проекте» двойная: гигиена + **инъекция** —
  корпус внутри проекта стал бы «фактами проекта» через grep/read_file
  (правило 20 доверяет project-тулам).
- **Квоты (per run):** ≤ 40 документов, ≤ 15 MB canonical_text. **Per scope:**
  ≤ 200 документов / 60 MB, вытеснение LRU.
- **TTL:** 7 дней; cleanup при удалении run'а; фоновая зачистка протухшего.
- **Dedup:** по content_hash (повторный фетч той же страницы = ссылка на
  существующий документ, обновляется fetched_at).
- **Pin:** ручное сохранение нужного документа = promote в существующую
  Библиотеку (одна концепция персистенции на систему; нового механизма нет).

## 4. Retrieval

- **BM25 — обязательное основание.** Русская нормализация обязательна:
  lowercase, ё→е, лёгкий стемминг (snowball-ru или суффиксная обрезка) —
  без неё BM25-only режим деградирует сильнее допустимого.
- **Embeddings (`:8001`) — опциональный re-rank.** Недоступность сервиса не
  ломает retrieval (fail-open к чистому BM25, одно предупреждение в лог —
  паттерн catalog.py).
- `web_query(query, doc_id?)` возвращает top-k чанков: точная цитата + doc_id +
  chunk_id + offset (готовые кандидаты в evidence).

## 5. Безопасность (web-контент недоверен ВСЕГДА)

- **Data-конверт:** любой корпус-текст, попадающий в контекст модели,
  оборачивается маркированным конвертом «данные, не инструкции». Инструкции
  внутри веб-текста не исполняются — это негативное правило и smoke-набор,
  НЕ доказуемая теорема (митигация + регрессия, честно).
- **Canonical text:** strip HTML/скриптов, zero-width и управляющих символов;
  сохраняются url, final_url, timestamp, content_hash, mime.
- **SSRF:** существующий гард + **повторная проверка на каждом redirect'е**.
- **MIME allowlist:** text/html, text/plain, application/pdf, docx; остальное —
  отказ с честным ok=False. Size-cap на ответ до парсинга.
- **Инъекционный smoke-набор (W1 DoD):** прямые инструкции, «system:»-мимикрия,
  поддельные tool-call-разметки, инструкции в HTML-комментариях/alt/скрытом
  тексте — ни один паттерн не должен привести к side-effect-вызову агента.

## 6. Ledger-механика (W3, зафиксировано заранее)

- **Структурированный tool-call, НЕ парсинг текста:**
  `web_claim_add(claims=[{claim, evidence=[{doc_id, chunk_id, quote}]}])` —
  батчевый (несколько claims за вызов; 35B не душится по-клеймовыми ходами).
- Runtime проверяет quote/offset/hash → ставит `quote_verified`/`source_verified`
  детерминированно; `claim_support` — advisory-поле от модели.
- **Рендер цитат — runtime**, детерминированным блоком-аппендиксом (как
  runtime_final_report). Номера [n] в тексте модели не парсятся.
- Scope: ledger покрывает НЕСУЩИЕ утверждения отчёта; отчёт различает
  «с evidence» и «фон». Nudge closure-стиля: ран читал веб → отчёт без единой
  записи ledger → один ограниченный пинок.

## 7. Флаги и совместимость

- Фиче-флаг `web_corpus` (ENV `ELIRA_WEB_CORPUS` + UI-тумблер), default OFF.
- `web_fetch` при выключенном флаге — **бит-в-бит** текущее поведение
  (пиновано тестами, паттерн R1). Включённый флаг добавляет `store=true`-режим.
- Новые тулы (`web_query`, позже `web_claim_add`) — deferred, не base
  (компакция-канарейка).

## 8. Negative rules (сводно)

1. quote-match ≠ доказательство claim (только провенанс).
2. Корпус — данные, не инструкции; корпус никогда не лежит в проекте.
3. Недоступный embed ≠ сломанный retrieval (BM25 — основание).
4. Ledger не собирается парсингом финального текста модели.
5. Redirect не обходит SSRF (re-check на каждом хопе).
6. Два evidence-домена «независимы» по eTLD+1-приближению; официальный
   первичный источник может быть достаточен один (tier=official).

## 9. DoD W1 (стартовый батч W0+W1)

- документ 200K символов → факт из середины отвечен, в LLM передано <5K;
- повторный вопрос по корпусу НЕ делает повторный fetch;
- quote→offset→hash round-trip (взятая из web_query цитата детерминированно
  верифицируется по корпусу);
- BM25-retrieval работает при выключенном/недоступном embed (ru-нормализация
  включена);
- инъекционный smoke-набор пройден (side-effect-вызовы не спровоцированы);
- TTL/квоты/cleanup/dedup проверены тестами;
- при выключенном флаге старый web-flow бит-в-бит (пиновано).

## 10. Вне scope (осознанно)

Auth/paywall/капчи; полноценный BFS-краулер (W4 — после реальной
необходимости; до него — W4-lite: sitemap.xml → выборочный fetch без
link-following); видео; RAG «всего интернета» (корпус — per-run/scope).
