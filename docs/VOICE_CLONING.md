# Голос Elira и границы клонирования

Клиентский контракт сверён с исходниками 18.10.2026. Голосовой UI использует
[voice/runtime.py](../backend/app/application/voice/runtime.py) и
[voice_routes.py](../backend/app/api/routes/voice_routes.py); это отдельный путь
от пользовательской транскрипции файлом через `audio-transcribe` skill.

## Действующий клиент

- `ELIRA_TTS_URL`: health, список voices и `POST /tts` с `text`/необязательным `voice`.
- `ELIRA_STT_URL`: health и multipart `POST /stt`; UI route ограничивает размер
  загрузки и выполняет blocking-запрос вне event loop.
- Ошибка сервиса передаётся явным результатом/HTTP error; наличие настроенного URL
  не подтверждает работающий сервис или качество речи.
- Автоозвучка получает принятый ответ; очередь, очистка Markdown и отмена остаются
  у текущих UI owners. Companion использует тот же голосовой путь.

Клиент не импортирует пользовательский ONNX и не реализует обучение голоса.
Выбор доступного голоса определяется реальным ответом сервиса. Default LAN URL
не доказывает конкретную модель или устройство исполнения.

## Клонирование

Это отдельная серверная задача, требующая явного запроса пользователя.
Сначала подтверждаются поддержка русского/клонирования и ресурсы, затем
сохраняется действующий HTTP-контракт либо добавляется совместимость в текущий
клиент. Второй независимый voice runtime не создаётся. Использование голоса
реального человека требует его согласия; dataset/model остаются вне Git.

Новый сервис проверяется на API-контракте, ошибках, latency, Stop/очереди и
реальном пользовательском примере до переключения. Прежние эксперименты Piper
не являются инструкцией установки текущего TTS.
