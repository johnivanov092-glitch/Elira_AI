## Метод

Во всех 21 погодных прогонах один сохранённый JSON (9–15 октября 2026), SHA-256 `b0f4d1073eba7659e2661a069b1392516ddd00365509140f7fb5aee868dcf78a`. Первые четыре группы имеют один запрос и одинаковую инструкцию навыка, различается только вывод скрипта. Нейтральный --input-json добавлен во все варианты, чтобы исключить сеть. Затем отдельно проверены инструкция и встроенный календарь. Настройки модели одинаковые; отдельные вызовы стохастические и не являются повтором идентичного provider payload.

Критерий таблицы: все 7 дат, дней недели, Tmin/Tmax, порывов и единиц совпадают с JSON и календарём. Правильный явный пересчёт км/ч в м/с допустим и проверяется отдельно. Повторные чтения и выбор навыка учитываются отдельно. «Таблица верна» не означает, что проверен каждый свободный комментарий модели.

## Изменения эксперимента

- `skills/weather/weather.py`: --input-json; день недели по datetime.date; подписи числовых колонок из daily_units; при отсутствии единицы — «не указана» и UNIT_WARNING, без угадывания.
- `skills/weather/SKILL.md`: раздельные единицы forecast/archive, проверка даты/дня/числа/единицы, использование полного stdout, дополнительные чтения только по конкретному основанию.
- `backend/app/application/calculation/calendar_ops.py`: точный григорианский календарь для 1–31 ISO-дат, валидация формата и существования даты; текущая локальная дата вместе с днём недели и UTC-offset.
- `backend/app/application/code_agent/tools/_math.py`: новая операция date_info существующего calc. Новый инструмент или executor не добавлен.
- `backend/app/application/code_agent/tool_schemas.py`: операция и её формат объявлены модели.
- `backend/app/application/code_agent/prompts.py`: runtime-дата включает вычисленный день недели.
- `backend/tests/test_calendar_tool.py`: границы високосных годов, переход года, неверные даты, пакет дат, часовой пояс и прежняя арифметика.

## Проверки и ограничения

- 65/65 тестов календаря, существующего калькулятора и промпта. Подтверждено свежим atlas_tests для worktree (4 тестовых файла).
- Atlas check: новых проблем 0, красных 0.
- Четыре варианта formatter сохраняют данные JSON; отсутствие единицы проверено отрицательным тестом.
- Проверяющий скрипт отклоняет подмену единицы, дня недели, чисел и отсутствие единицы температуры.
- Консервативный первый аудитор предполагает порядок min/max и только три числовых значения: четыре допустимых раскладки проверены дополнительно через verify_weather_layouts.py (обратный порядок max/min, дополнительная колонка погоды, оба представления единиц). Исходные предупреждения аудитора сохранены, а не скрыты. Это локальные проверки эксперимента, не изменение golden.
- `golden/tasks.json` побайтово совпадает с исходным снимком. Полный golden и полный pytest в этом этапе не запускались. Результат не означает стабильных 29/29 или готовности всего переноса Web к выпуску.
- Новый блокирующий guard и переписывание ответа не добавлялись. На последней выборке целевые поля таблицы проходят проверку, но свободный текст и лишние действия остаются отдельными ограничениями.
