# Саморазвитие Elira: сквозная проверка и web

Дата: 26 сентября 2026. Рабочая ветка: `codex/autonomy-recovery`.

Исторический отчёт об этой приёмке и установке: ветка, active-релиз и отсутствие
commit/push ниже описывают тот момент. Исходники позже объединены в `main`;
[актуальные проверки и состояние запуска](AUTONOMY_ADVISOR_ACCEPTANCE_RU.md)
не следует выводить из исторического `/health`.

## Что реализовано

Qwen выбирает разовое действие, использование навыка или развитие новой
возможности. `task_decide` сохраняет это решение; существующие
`skill_create → skill_check → skill_publish → skill_load` обеспечивают локальную
историю и применение пакета. Повторный `skill_load` явно обновляет текущий
контекст до новой проверенной версии, включая изменённые скрипты.

Успешный exit процесса отделён от корректности результата. `result_verify`
исполняет самостоятельную проверку файлов, читает свежий структурированный
отчёт и связывает вердикт с SHA-256 результатов. Неудача или изменение входов
снимает прежнее подтверждение, в том числе после Resume. Sandbox сохраняет
исходники и отдельные квитанции выполнений. Повтор одинаковых завершённых
команд вызывает диагностическую подсказку; новый PID не считается продвижением.

Автоматический выбор коммерческой BOM-проверки по слову «BOM» убран. Проверка
спецификаций остаётся доступным инструментом, который выбирает сама модель.
Старый классификатор и Laya не возвращались. Навык служит расширяемой
структурированной подсказкой: применимость, действия, проверки, ограничения.
Второй agent loop, executor или registry не добавлен.

## Неудачные попытки и границы результата

Первый исходный прогон в `.scratch/autonomy-goal-acceptance/` не прошёл:
ложная BOM-классификация, отсутствие сохранённого навыка, повторение неудачных
команд. Первая попытка после исправлений в
`.scratch/autonomy-goal-acceptance-fixed/` также не прошла: модель дважды
неверно оформила YAML навыка, затем долго генерировала без завершённого действия.
Этот прогон остановлен и сохранён как неудачный. В ответ `skill_create` добавлен
точный формат пакета; ошибка YAML теперь содержит диагностику парсера.

Финальные три этапа выполнены на неизменном кандидате без ручного исправления
созданных Qwen навыков. После них отдельно добавлены web-подсказки, источники
браузера, оформление ссылок и две узкие правки диагностики: учёт реальных
`execution_status=error` и показ `unverified` в контексте после изменения входа.
Исходный и итоговый состав файлов записан в `source-manifest.json` и
`final-release-source-manifest.json`; проверки этих дополнений выполнены отдельно.

Это доказательство конкретного пути создания, исправления и повторного
использования возможности. Оно не гарантирует правильность любой будущей
задачи: содержательность проверок и выбор подхода по-прежнему зависят от Qwen.
Сквозной сценарий использовал публичный backend-цикл, а не ввод через Tauri UI.

## Web при включённом thinking

Thinking уже сохранялся между инструментальными шагами общего цикла.
Предварительный структурированный план сам инструменты не исполняет: он может
выбрать группу web и запланировать исследование. Добавлена подсказка: при
недостатке сведений прочитать первичную документацию, уточнить план, выполнить
задачу и проверить результат. Постоянный поиск для каждой задачи не вводится.
При сохранении навыка модель получает указание записать ссылки и применимую
версию API/библиотеки, отличая документацию от проверенного выполнением.

`web_search`/`web_fetch` уже сохраняли источники. Браузер дополнен такой же
квитанцией: фактический конечный URL и прочитанный DOM, без текста переданных
действий. Источники и цитаты сохраняются в прежнем RunJournal и переживают Resume.

Живой прогон `.scratch/autonomy-thinking-web-final/result.json`:
Qwen с thinking=true и reasoning_effort=low самостоятельно вызвала `web_fetch`
для официальной документации Python 3.10, продолжила ответ и сохранила две
сопоставленные цитаты. `done.complete`, 31,312 с. Запрошенный ответ о `newline=''`
соответствует прочитанному разделу. Отдельный реальный browser-вызов получил
DOM той же страницы и две квитанции источников. Полный путь
search → fetch → browser → ответ → Resume проверен интеграционным тестом с
контролируемой моделью и сетевыми ответами; это не дополнительный живой прогон Qwen.

Один ранний web-запуск остановлен до инструментов, чтобы последовательно
использовать единственный слот Qwen. Он сохранён отдельно и не считается pass.
Сохранение ссылок непосредственно в новом навыке в живом web-прогоне не
проверялось: тот запрос требовал только ответ без создания файлов.

Перед установкой обнаружен оставшийся staged backend прежнего релиза: его

проверил точную OS identity и instance/token, штатно остановил этот процесс,
затем вызвал существующий `apply_pending` для остановленного приложения.
Тот сохранил SQLite, установил кандидат и передал работу обычному циклу supervisor.
Стабильное ядро `scripts/elira_release.py` этим пакетом не изменяется.

Отдельная старая запись Workflow от 26 августа была в `running` без живого
процесса и связанных UI requests. Её обычный startup recovery не закрывал;
она удерживала обновления при работающем приложении. После установки UI и
supervisor завершились; HTTP API уже не работал. Пользователь явно согласовал
отмену этой прежней задачи, и она переведена в `cancelled` через тот же
`cancel_workflow_run`, который использует штатный API, при остановленном приложении.
Нет незавершённых Workflow; вход, контекст и результаты записи сохранены.
История чатов после отмены также неизменна. Доказательства:
`stale-workflow-cancelled.json` и `final-state.json` в каталоге приёмки.
Приложение на момент завершения работы закрыто; для следующего обычного запуска
выбран установленный `autonomy-recovery-20260926`.

Очистка одного прежнего тестового окружения была отклонена автоматической
проверкой с причиной `blocked by policy`; удаление повторно не выполнялось.
Исходники текущего пакета оставлены в рабочей ветке без commit/push.
