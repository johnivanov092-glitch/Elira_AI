# Самостоятельные изменения приложения, MCP и обучаемые подсказки

Статус на 27 сентября 2026 после установки: рабочий релиз
`autonomy-voice-20260927` активирован штатным менеджером релизов; desktop и backend
запущены. Релиз содержит исходники commit `990e29e61b9b2f710ef74711159a62911d8e75b6`.
Проверки поставки и озвучки описаны в последних разделах документа.
MCP attempt5 и UI-02 CREATE сохраняют исходные FAIL; отдельная диагностика MCP reuse
прошла. Отдельный ремонтный прогон UI также завершился FAIL: модель принудительно
остановила процессы тестовой установки до штатного переключения релиза.
Этот документ разделяет реализацию,
контролируемые проверки и приёмку на реальной Qwen.

Пути `.scratch/` и `.runtime/` ниже относятся к локальным доказательствам и
не публикуются на GitHub. Датированные результаты и их хеши сохранены; они не
означают, что указанный тогда процесс работает сейчас. Раздел «Финальный кандидат
runtime» ниже сохраняет исторический результат до установки рабочего релиза.

## Область работы

- Проверить создание функции UI/backend в отдельной установке, наблюдаемое
  исправление, использование после перезапуска и восстановление релиза.
- Проверить самостоятельное создание MCP по документации, адаптацию существующего
  подключения после смены API и применение в новом чате.
- Добавить локальную обучаемую рекомендацию навыков и отдельно сравнить первый
  выбор Qwen с подсказкой и без неё. Такой диагностический выбор не заменяет
  выполнение пользовательской задачи.
- Перед разработкой исследовать подходящие установленные и внешние решения;
  сохранять источники адаптированного кода, версии и результаты проверки.

## Реализация в исходниках

| Компонент | Что делает | Как меняется |
| --- | --- | --- |
| Qwen | Анализирует цель, выбирает инструменты и проверяет результат | Веса LLM этой задачей не обучаются |
| CPU-классификатор | Предлагает подходящие сохранённые навыки | Обучает веса по проверенным исходам, хранит версии |
| Навык | Инструкция и при необходимости код для повторяемой работы | Агент создаёт или адаптирует проверяемый пакет в локальном Git |
| MCP | Подключает инструмент через общий протокол | Агент пишет/обновляет адаптер и конфигурацию существующего runtime |
| Релиз UI/backend | Заменяемая версия приложения | Кандидат, сборка, проверка, переключение и откат |
| Ядро запуска | Запускает и восстанавливает приложение | Отделено от заменяемого релиза |

Используется прежний agent loop, executor, RunJournal, каталог навыков и MCP
registry. Новая CPU-модель `skill_advisor.py` обучает веса Multinomial Naive Bayes
на наблюдённых положительных исходах. Отдельная LLM, GPU и зависимости не нужны.
Qwen получает рекомендации, полный каталог остаётся доступным.

`TaskOutcome` связывает проверку с выбранным навыком и его точной версией,
входными и выходными файлами. Загрузка другой версии снимает актуальность
предыдущей проверки. Обучение требует завершённой задачи и текущих хешей
содержательного отчёта и всех заявленных результатов. Ошибки сети и сам текст
«готово» не используются как метки.

При `reuse` проверяется та же закреплённая версия пакета, которая была загружена
в задачу. Публикация другой версии не аннулирует корректный старый снимок;
изменение файлов старого снимка обнаруживается также после восстановления задачи.
Пропущенные аргументы инструментов возвращаются модели как `failed`, чтобы она
могла исправить вызов; отдельные запросы Workflow к пользователю сохраняются.

Признаки запроса очищаются от путей, URL, имён файлов и числовых идентификаторов.
Одинаковая нормализованная задача не попадает одновременно в обучающую и
контрольную части. Модель сохраняет производные признаки и ссылки на проверку,
а не ещё одну полную копию текста диалога. Исходные факты остаются в RunJournal.

Перед активацией версия сравнивается на контрольной части с выбором по частоте
и прежней моделью. Это внутренняя диагностика ассоциаций; она не измеряет пользу
подсказок для Qwen на новых задачах. Старые и текущие версии навыков различаются;
проверенность старой версии не переносится автоматически на новую.

Инструкции исследования предлагают выбор между готовым, адаптированным и новым
решением. `SOURCES.md` сохраняет URL, версии/commit, лицензии и атрибуцию
заимствованного кода, внесённые изменения и проверки. Изменение MCP использует
копию кандидата и существующие операции подключения; публикация пакета и
регистрация MCP не являются единой атомарной транзакцией.

## Стенды и критерии

### MCP

Harness: `backend/tests/smokes/autonomy_mcp.py`.
Доказательства: `.scratch/autonomy-mcp-acceptance/`.

Тестовый склад имеет несколько страниц товаров. Первый запрос требует
исследовать первичные материалы, создать MCP и получить полный CSV. Затем
старый API возвращает 410 и становится доступна новая версия с другой
пагинацией. Модель должна исправить существующий адаптер. Третий процесс
с пустой историей использует его на новых данных.

Pass требует реальных namespaced MCP-вызовов, HTTP-аудита, правильных данных,
ошибки и исправления в журнале, сохранённого исходного entrypoint в Git,
нового чата без переписывания пакета и неизменной production-конфигурации.
Путь интерпретатора внутри `.venv` не доказывает, что исходник адаптера сохранён.

### UI/backend

Harness: `backend/tests/smokes/autonomy_ui.py`.
Доказательства: `.scratch/autonomy-ui-acceptance/`.

Цель — скачать архив выбранной папки диалогов. Подготовлены тестовые чаты,
одинаковые названия, кириллица, длинный текст и чат вне папки. Oracle сравнивает
полноту архива с данными, а не только HTTP-статус. Исправление проверяется
маркированной инъекцией регрессии только в неактивном тестовом кандидате.
Откат отдельно проверяет сохранение данных, созданных после обновления.

У платформы отдельные данные, процессы, порты и browser origin. Внешний
тестовый адаптер заменяет только запуск окна браузером; механизм релизов
остаётся прежним. Эта приёмка не равнозначна проверке настоящего окна Tauri.

Во второй фазе Qwen получила HTTP 410 прямым запросом к старому API, но не
вызвала старую версию через native MCP до исправления. Она самостоятельно
обновила существующую интеграцию, сохранила новую версию и успешно применила её.
Это подтверждает функциональное исправление, но не заменяет пропущенный шаг
исходного запроса. Фаза 3 исходного сценария остаётся незапущенной.
Последующая диагностика имеет отдельные run ID, рабочую папку, журнал и вердикт
`diagnostic_reuse_ok=true`. Она не меняет исходный FAIL и не открывает warmup gate.

В отдельной диагностике Qwen загрузила сохранённый `warehouse-mcp` и использовала
native `warehouse__get_stock_report`. Пакет `f6b64733289f465d84b109df133be68e`,
Git `3fe778df43289c42c23ada0ec4391199d0d624fd`, зависимости, receipts и MCP/config
не изменились. Агент создал только локальный вариант экспортера для новых имён
файлов и проверяющий скрипт в новой рабочей папке.

Обратная связь проверена на реальной ошибке: на шаге 13 runtime отклонил
проверку отчёта самим собой; на шаге 15 были проверены CSV, но служебный отчёт
ещё оставался в `task_decide.targets`. После коррекции runtime на шаге 16 Qwen
сама исправила общий список результатов на шаге 17 и выполнила свежую успешную
проверку на шаге 18. Технических подсказок от оператора и автоматического удаления
targets не было.

При завершении диагностики исходные phase/event/journal/control-файлы attempt5,
четыре прежних CSV и опубликованный пакет сохранили хеши. В общий isolated DATA

backup нового проверяющего скрипта и обучения; они перечислены в отдельном
вердикте. Полная неизменность всех shared DATA не заявляется. Дочерних процессов
и HTTP-listener стенда не осталось, production не изменён. В трассах и созданном
коде не обнаружено чтений oracle или ожидаемых ответов. Controller и worker
запускались через stdin; это не изоляция файловой системы правами ОС.

Локальные доказательства: `.scratch/autonomy-mcp-acceptance-attempt5/REPORT.md`,

`.scratch/autonomy-mcp-reuse-diagnostic/evidence/diagnostic-verdict.json`.

### Реальное обучение и файловый контракт URI

В isolated DATA сохранены **2 реальных положительных примера, 1 класс навыка**.
Это завершённая адаптация MCP во второй фазе attempt5 и отдельный reuse.
`active` у модели остаётся `None`: 2 train groups, 0 holdout groups,
`promote=false`, причина `insufficient_evidence`. Сравнение качества подсказок
для Qwen не выполнено; успешные задачи не доказывают качество классификатора.

Первая фаза attempt5 завершилась корректным результатом, но не стала обучающим
примером: Qwen записала URL в список файловых входов. Runtime нормализовал его
как несуществующий локальный путь; обучение отклонило его с
`no_current_bound_result_check`. Эта разница между завершением и допустимостью
обучающего примера сохранена в доказательствах.

После завершения замороженной диагностики в root-исходники применён узкий URI
file-contract patch: URI в файловых полях `task_decide`/`result_verify` возвращает
модели ошибку аргумента с объяснением; обычные относительные, абсолютные и UNC-пути
сохранены. Guidance/schema уточняют файловый контракт. **44 focused-проверки прошли**;
это точечная проверка, не повтор живой MCP-приёмки после патча.
Запись применения: `.scratch/autonomy-advisor/uri-file-contract-applied.json`.
Позже патч включён в проверенный кандидат attempt6; production не обновлён.

### UI: остановка, перезапуск и публичный Resume

Первый UI-прогон остановлен: модель обнаружила путь к тестовому harness в
аргументах процесса и прочитала код внешней оценки. Изменений функции ещё не было;
такой прогон не считается независимой приёмкой. Исходные доказательства сохранены

приложения отделён от оценки; новый набор диалогов формируется после фиксации
реализации. Это тестовое разделение, не изоляция правами ОС.

UI-02 create остановлен watchdog по исходному лимиту **1200 секунд**; полный
интервал до завершения отмены составил 1235,937 секунды, 36 шагов. Результат
`cancelled`, `resumable=true`; это не PASS функции и не самостоятельное
восстановление после сбоя. Исходный `phase-create.json` сохранён.

Затем выполнен контролируемый перезапуск тестового backend/browser runtime.
Цель, исходный запрос, план из **6 пунктов**, **2 закреплённых навыка**,
source epochs, TaskOutcome, исходники и receipt совпали до и после перезапуска.
План находится в `task_planner.db`; пустое поле `todo` RunJournal не означает
отсутствие плана. Изменился instance ID backend.

Строгий verdict неизменности всех БД остался **false**:
`controlled-restart-verdict.json` содержит `changed=["databases"]`.
Изменились логические дампы `tool_registry.db` и `workflow_engine.db`.
Точные строки до перезапуска не были сохранены, поэтому считать различия
доказанно безвредными служебными обновлениями нельзя. Совпадение цели, плана,
закреплённых навыков и исходников не подменяет этот непрошедший критерий.

### Одобренный пакет памяти и RAG

После явного согласия пользователя исправления памяти и RAG включены в текущую
работу. Это изменения runtime, а не добавление одноимённых навыков.

- `memory_add` и `remember` теперь сохраняют неподтверждённые выводы как
  `agent_note`. Пользовательское происхождение требует буквального соответствия
  текущему raw request из RunJournal; model-supplied `source` не используется.
  Сохраняется `source_ref=run:<id>`. Исправление собственной заметки не повышает
  её доверие; агентская заметка не перезаписывает пользовательский факт и не
  усиливает его через дедупликацию. Ручная запись пользователя через UI сохранена.
  Миграция добавляет только поле происхождения, не переопределяя старые записи.
  65 focused tests и 14 subtests прошли; проверены настоящая SQLite, повторное
  открытие, пользовательская поправка, сохранность пользовательской строки и
  отделение приложенного контекста и внутреннего delegate prompt от raw request.
  Conditional UPDATE также проверяет прежние text/category/source/source_ref:
  конкурентная пользовательская поправка или удаление возвращает конфликт,
  а не перезапись или ложное сообщение об успешном сохранении.
- Project Corpus готовит полную версию одного файла вне write transaction,
  затем одной SQLite-транзакцией заменяет chunks и manifest. Обе выборки поиска
  читают один снимок. Проверены отказ второго chunk, SQL failure после частичной
  вставки и при записи manifest, конкурирующая публикация, retry, scope и stale
  cleanup. Старые повреждённые managed sources скрыты до успешного reindex;
  чтение ничего не удаляет. 122 focused tests прошли, после bounded-read
  уточнения ещё 13 corpus tests. Гарантия относится к одному источнику в SQLite,
  не к атомарному снимку всей живой файловой системы.

Старый release receipt `0fbb…` их не покрывает.
