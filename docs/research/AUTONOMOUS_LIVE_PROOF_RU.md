# Реальная Qwen: создание и повторное использование навыка

Дата: 2026-09-26, 12:25–12:29 UTC. Проверен текущий рабочий код через публичный `stream_code_agent`, реальный HTTP provider и штатный `runtime_control`; `chat_fn`, ответы модели и результаты tools не подменялись. Feature-код во время проверки этим исполнителем не менялся.

Это исторический первый сценарий, не статус последнего релиза.
[Последующие приёмки и текущие ограничения](AUTONOMY_ADVISOR_ACCEPTANCE_RU.md)
ведутся отдельно. Пути `.scratch/` ниже — локальные доказательства, не файлы GitHub.

**Подтверждено:** Qwen самостоятельно написала отсутствующий Python-навык, проверила его, опубликовала в локальный Git, загрузила, применила и затем использовала ту же версию в отдельном новом запуске. Оба выходных файла побайтно совпали с независимыми эталонами. Первый поток после применения прервался из-за консольного логгера проверочного helper; успешный финальный `done` получен только во втором запуске.

## Ограничения и очистка

После последнего успешного tool первого запуска helper пытался вывести текст subprocess через Windows CP1251 и получил `UnicodeEncodeError` для U+2567. Журнал сохранил `exit=0`, корректные bytes/BOM/CR/trailing-LF проверки; UTF-8 файл отдельно совпал с эталоном. Вывод строк subprocess уже был искажён декодированием, хотя `read_file` показывал корректный русский текст. Исправлен только временный helper: UTF-8 для собственной консоли и `PYTHONIOENCODING`; создание не повторялось. Новый независимый reuse завершился штатно. Первый run нельзя считать полностью прошедшим до финального ответа.

Qwen написала `tempfile.TemporaryDirectory()` в selftest. В первом запуске его краткоживущие fixtures использовали стандартный OS temp, а не scratch; проверки завершились и вышли из контекстов TemporaryDirectory. Имена этих директорий не журналировались, полная изоляция временных файлов первого запуска не подтверждена. Для второго запуска `TMP/TEMP/TMPDIR` явно перенаправлены внутрь scratch. Постоянные данные приложения и история навыка были изолированы с начала проверки.

Охват ограничен одним небольшим Python-навыком с известным контрактом и одним повторным применением. Самоизменение UI/backend, создание MCP/API, установка GPU-моделей, выбор навыка без заданного имени, восстановление после плохого пакета и длительная автономная работа требуют отдельных предметных проверок. Зацикливания модели не было; автоматическую отмену эта проверка не задействовала.

Оба helper-процесса завершились. Перед очисткой проверен точный путь `D:/AIWork/Elira_AI/.scratch/autonomous-live-proof`: 59 созданных проверкой файлов, 688913 байт, reparse points отсутствуют. Автоматическая проверка исполнения отклонила как удаление этой конкретной папки, так и более узкое удаление файлов по отдельности: `blocked by policy`; обе команды не исполнялись. Поэтому временные helper, fixtures, runtime DB, журналы, навык и его изолированная Git history пока сохранены в этой папке. Production-каталог навыков не пополнялся.
