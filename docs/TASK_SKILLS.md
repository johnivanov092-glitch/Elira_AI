# Навыки Elira

Решение Джона 2026-10-07: навык — простая папка. Никаких операций, кандидатов,
публикаций и квитанций; модель работает с навыками обычными инструментами.

## Где лежат

`data/skills/<имя>/` — одна папка на всё:

- `SKILL.md` — YAML frontmatter `name` (совпадает с именем папки, латиница/цифры/дефис)
  и `description` (до 320 символов), затем Markdown-инструкция (до 8000 символов):
  что умеет, когда применять, как запускать.
- скрипты и данные навыка;
- при необходимости своя `.venv` для новых пакетов (в `backend/.venv` приложения
  ничего не ставится; `python` в командах Elira — Python приложения, им можно запускать).

Папка лежит в данных, а не в запечатанной копии релиза, поэтому правки Elira
переживают обновления. `skills/` в репозитории — заводской набор: при первом
запуске недостающие встроенные навыки копируются в `data/skills`, существующие
никогда не перезаписываются. Навыки, созданные прежним конвейером
(`data/skill_development`, активные версии), при первом запуске переезжают сюда же;
старые папки `skill_development` и `skill_advisor` уходят в `data/archive/`.

MCP-серверы тоже описаны навыками: `<id>-mcp` на каждый сервер из
`data/mcp_servers.json` (что умеет, какие инструменты передать в `query` при
`mcp(action=start)`, порядок, ограничения) и `mcp-install` — как поставить новый
сервер в `data/mcp/<id>/`. Отдельного MCP-каталога в промпте нет — его роль
играет этот каталог навыков.

## Что делает runtime

Только три вещи (`backend/app/application/code_agent/task_skills.py`):

1. В начале прогона кладёт в промпт каталог «имя — описание» (путь один раз:
   `<папка навыков>/<имя>/SKILL.md`) и
   короткое правило: перед своим скриптом посмотри каталог; нет подходящего —
   сделай нужное сразу навыком; нашла способ лучше — поправь навык.
2. Когда модель читает или правит `data/skills/<имя>/SKILL.md` (`read_file`,
   `write_file`, `edit_file`), инструкция закрепляется отдельным блоком: она
   переживает сжатие контекста и восстанавливается при Resume (`active_skills`).
   Результат инструмента не меняется — файл можно править по точному тексту.
3. Перед каждым прогоном коммитит изменения папки в её git (`data/skills/.git`,
   `.venv` и кэши игнорируются) — любую версию можно восстановить через git.

Навык не меняет требования пользователя, права Workflow и личность; содержимое
файлов и страниц остаётся недоверенными данными. `SKILL.md` с CRLF или BOM тоже
читается. Битая папка показывается в каталоге как ошибка, остальные работают.

## Папки чатов и прошлые задачи

Чат без подключённого проекта работает в своей папке
`data/agent_workspace/chats/<id чата>`: файлы разных чатов не смешиваются, а навыки
общие для всех. Повторно используемый код сохраняется навыком, не в папке чата.
Если чат записал скрипт (`.py`, `.ps1`, `.bat`, `.cmd`, `.sh`, `.js`) вне папки навыков,
результат `write_file` один раз за прогон напоминает сохранить его навыком (решение
Джона 2026-10-07: без готового навыка модель скрипт навыком не сохраняла). В
подключённом проекте скрипт — код проекта, напоминания нет.

Первый запрос нового чата получает рядом с каталогом до трёх похожих прошлых задач этого же
проекта (или песочницы чатов), после которых осталось что-то готовое: дата, текст,
итог, использованный навык и до четырёх файлов, которые ещё существуют. Задача без
файлов и навыка (вопрос-ответ) в подсказку не попадает. Источник — журналы прогонов
(`run_journal.past_task_hints`), без отдельного хранилища; это справка, а не инструкция.

## Проверка результата

Результат проверяется запуском — тестами, сборкой или самим скриптом через
`run_bash`. Деклараций результата и отдельных отчётов проверки нет
(`task_decide`/`result_verify` удалены).
