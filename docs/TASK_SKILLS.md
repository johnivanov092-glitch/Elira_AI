# Выбор и жизненный цикл навыков

Elira выбирает навыки по смыслу задачи в существующем agent loop. Отдельного
классификатора, LLM-судьи, переключателя личности или таблицы ключевых слов нет.

Подходящий установленный навык помогает работе, но отсутствие навыка не
останавливает задачу. Агент исследует окружение и документацию, создаёт
недостающее средство доступными инструментами, проверяет и применяет его в
текущем запуске. Полезное проверенное решение можно сохранить с инструкцией
и зависимостями. Это руководство для существующих file/shell/MCP-инструментов;
пакеты публикуются через существующий `runtime_control` и локальный Git.

## Создание и атомарная публикация

`skill_create(name)` возвращает `candidate_id` и каталог. Для улучшения существующего
навыка туда копируются его исходники; Python/npm окружение создаётся отдельно для
кандидата. Агент пишет `SKILL.md`, скрипты и фиксирует зависимости обычными file/shell
инструментами. Путь кандидата при публикации не меняется, поэтому его окружение
не переезжает и не подменяет окружение действующего пакета.

`skill_check(name, config={candidate_id, command})` запускает реальную проверку
через существующий shell runtime со Stop. Код проверки должен проверять результат,
а не просто печатать «OK». Исходники и установленные зависимости хешируются до и
после проверки; изменившийся пакет нужно проверить повторно. `__pycache__` и
временный кэш pytest не входят в содержимое пакета.

`skill_publish(name, config={candidate_id})` записывает исходники и lock-файлы в
локальный Git без remote и атомарно обновляет указатель активной версии.
`skill_load` может использовать её в той же задаче. Старый run сохраняет точную
версию своих инструкций и путь к скриптам. Для MCP агент регистрирует/запускает
проверенный сервер прежними `mcp_upsert`/`mcp_start`; новый registry не создаётся.

`skill_status(name)` показывает активную версию, `skill_rollback(name)` включает
предыдущую, `skill_discard(name, config={candidate_id})` удаляет выбранный неактивный
кандидат. Рабочая и резервная версии сохраняются. Все изменения проходят прежний
Workflow permission mode; Bypass не получает дополнительных подтверждений.
История и пакеты находятся в `data/skill_development/` и не коммитятся в Git
приложения. Пакет выполняется отдельным процессом; его Python не импортируется
механизмом навыков в backend.

## Контракт

1. `task_skills.catalog_context()` читает установленный `skills/` и активные
   опубликованные пакеты из локального `data/skill_development/`, валидирует
   пакеты и добавляет только метаданные отдельным сообщением после стабильного
   системного префикса. Каталог не фильтруется по первой догадке о домене.
2. Модель вызывает `runtime_control` с `skill_list` или `skill_load`. При скрытой
   схеме доступен существующий `capability_load(group="runtime")`.
3. Обе операции идут через прежние registry/ToolExecutor/dispatch и относятся
   к чтению. Загрузка инструкции не запускает MCP, shell или скрипты пакета.
4. Цикл принимает успешный снимок, проверяет целостность и бюджет и закрепляет
   один блок активных инструкций существующим `pinned_message_ids`.
   Полное тело не дублируется в tool history. Порядок tool_calls → tool results
   сохраняется при вставке блока.
5. Событие `skills_changed` записывает снимки в существующее `active_skills`
   журнала. `tool_call.skill` содержит имя, заголовок, hash, причину выбора
   и признак повторной загрузки. UI показывает этот receipt в обычной строке
   инструмента; сохранённые диалоги используют тот же формат.
6. Resume/внутреннее продолжение восстанавливают снимки того же run_id. Новый
   запрос начинает отдельный набор навыков. Снимки не становятся личной памятью.

## Границы

- Корень инструкций принадлежит установке Elira; аргументы модели, подключённый
  проект, история, Library и Web не могут назначить другой корень.
  Новый пакет становится виден через явную операцию `skill_publish`, а не от
  наличия произвольного `SKILL.md` в пользовательском проекте.
- Имя пакета валидируется, выход через traversal/symlink запрещён. Пакеты
  с ошибками не превращаются в успешный пустой результат.
- Рекомендации навыка подчинены пользователю и Workflow. Личность, настроение,
  sampling, базовые инструменты и обязательные общие проверки не меняются.
- Выбор остаётся решением модели: наличие каталога не гарантирует правильного
  выбора на любом запросе. Неудачный выбор исправляется через полный skill_list.
- Если после начала работы с файлами/системой навык не выбран, цикл добавляет
  одно короткое напоминание в следующую существующую итерацию. Оно не блокирует
  инструменты, не назначает навык по ключевым словам и не создаёт вызов LLM
  только ради классификации. В обычной беседе напоминание не появляется.
- Короткие беседы не получают тела 12 инструкций. Каталог занимает дополнительный
  контекст, skill_load добавляет итерацию агента; влияние нужно измерять вместе
  с качеством выбора, отдельно от TTFT первого текста.

Формат пакета, лимиты и состав набора описаны в [skills/README.md](../skills/README.md).

## Проверки

`backend/tests/test_task_skills.py` проверяет реальный adapter/loop/journal,
отказ произвольным путям, полный каталог после ошибочного выбора, бюджет,
дедупликацию, normal/fallback compaction, Resume и изоляцию нового разговора.
`frontend/src/workspace/ToolCallGroup.skills.test.tsx` проверяет отображение
успешной и неуспешной загрузки в существующем интерфейсе.

Живой сценарий: беседа → диагностика Python → беседа; отдельно запросы по
Windows/Linux, сети, Java, JS/TS, Rust, SQL и развёртыванию. Оценивать выбранные
навыки, реальные инструментальные действия, prompt/cache/TTFT и корректность
ответа отдельно. Наличие подходящего skill не доказывает успешность самой задачи.

Повторяемая диагностика первого выбора (предложенные инструменты не исполняются):

```powershell
backend\.venv\Scripts\python.exe -u backend/tests/smokes/skill_selection_eval.py --live --output .agent/evals/task-skills/live
```

Сохраняются исходные запросы, ответы, seed, prompt/cache/TTFT и предложенные
навыки. `deferred_or_missed` означает, что первый вызов выбрал другой инструмент;
для оценки окончательного выбора нужен полный пользовательский путь.
